The important distinction is:

Skill Gap Analyzer = determines what the learner is missing and why.
Revision Engine = determines what the learner should revise now and in what sequence.

They should work together, but they should not be the same algorithm.

Your Capacity Connect proposal already identifies AI Skill Analyzer → skill-gap identification, while the revision design establishes a deterministic learner model based on evidence, competency, confidence, dependencies and learning history.

Below is the architecture I recommend, followed by a full implementation prompt you can give to your coding agent.

3. Skill gap types

I recommend these categories.

MISSING

The learner has little or no evidence of competency.

required = 70
current = 20
WEAK

The learner has evidence but is below the required level.

required = 80
current = 48
AT_RISK

The learner currently performs adequately but memory/retention is deteriorating.

required = 70
current = 73
forgettingRisk = high
UNCERTAIN

The learner appears capable but there is insufficient evidence.

required = 80
current = 78
confidence = 0.25

This is important because high score ≠ proven mastery. Your revision architecture already explicitly separates competency and confidence for this reason.

MEETS_REQUIREMENT
current >= required
confidence >= threshold
EXCEEDS_REQUIREMENT
current significantly > required
confidence high

These skills should generally not appear as gaps.

6. Skill-gap calculation

I would use this as the core deterministic formula.

First:

RawGap =
RequiredLevel - CurrentCompetency

Clamp:

Gap = max(0, RequiredLevel - CurrentCompetency)

Normalize:

GapSeverity =
    Gap / RequiredLevel × 100

Example:

Required = 80
Current = 40

Gap = 40

GapSeverity =
40 / 80 × 100
= 50
7. But gap severity alone isn't enough

A 40-point gap in an unimportant skill shouldn't necessarily outrank a 20-point gap in a critical prerequisite.

Therefore calculate:

GapPriority =
    0.35 × GapSeverity
  + 0.20 × Importance
  + 0.15 × DependencyImpact
  + 0.10 × EvidenceUncertainty
  + 0.10 × ForgettingRisk
  + 0.10 × ErrorSeverity

This should be configurable.

The revision report already establishes the principle of combining multiple normalized signals instead of using only competency.

8. Add a criticality multiplier

I would also introduce:

CriticalityMultiplier

For example:

Core requirement:
1.25

Important:
1.10

Normal:
1.00

Optional:
0.80

Then:

FinalGapPriority =
    GapPriority × CriticalityMultiplier

This prevents an insignificant skill from dominating the learner's development plan.

19. Gap categories

The analyzer should distinguish:

For example:

knows concept
but performs poorly in real scenarios
Performance gap
correct but extremely slow
Retention gap
previously mastered
but recall has declined
Evidence gap
high score
but insufficient evidence
Prerequisite gap
advanced skill weak because foundation is weak

This makes the AI analysis much more actionable.

20. Evidence hierarchy

Not all evidence should have equal weight.

I would define:

Strong evidence
    ├── Assessment result
    ├── Retrieval test
    └── repeated independent practice

Medium evidence
    ├── Practice
    └── guided assessment

Weak evidence
    ├── Lesson completion
    └── self-reported confidence

Important:

Lesson viewed ≠ competency proven

This prevents bad skill-gap detection.

Your revision design already requires learning events to record correctness, response time, hints, confidence and attempts, which provides the right evidence foundation.

The responsibility boundary should be very strict:
Module	Main question	Source of truth
Competency Engine	What does the learner know?	Learning evidence
AI Skill Gap Analyzer	What is the learner missing?	Required vs current competency
Revision Engine	What should be revised now?	Gap + memory + dependencies + errors
Recommendation Engine	What should be learned next?	Skill gaps + curriculum
LLM	How should we teach/explain it?	Deterministic context

This separation will make the system much easier to debug and demonstrate.
